# Smart Factory 예지보전 시스템 User Class 정의서

## 1. 목적

시스템을 직접 사용하거나 결과에 영향을 받는 사용자 집단을 역할, 권한, 사용빈도, 기술수준, 정보요구 및 주요 불편사항에 따라 구분한다. User Class는 운용 시나리오, 기능 요구사항, 화면설계 및 접근권한 정의의 기준으로 사용한다.

## 2. User Class 식별기준

- 수행하는 업무와 책임이 다른가?
- 필요한 정보의 상세수준과 사용빈도가 다른가?
- 생성·수정·승인할 수 있는 데이터와 권한이 다른가?
- 정상상황과 비상상황에서 요구되는 대응시간이 다른가?
- 시스템 사용능력과 교육수준이 다른가?

## 4. UC-01 생산 작업자

### 4.1 역할과 책임

- 담당 설비의 현재상태와 경보를 확인한다.
- 설비 소음, 냄새, 발열, 진동 등 현장상태를 점검한다.
- 허용된 범위에서 1차 안전조치를 수행한다.
- 경보 확인, 현장관찰 및 조치결과를 시스템에 기록한다.
- 정비 담당자에게 필요한 현장정보를 제공한다.

### 4.2 사용자 특성

| 항목 | 내용 |
|---|---|
| 기술수준 | 설비운전 숙련, IT 사용능력은 초급~중급 |
| 사용환경 | 소음과 이동이 많은 생산현장, 장갑 착용 가능 |
| 필요정보 | 설비상태, 경보등급, 영향, 간단한 조치절차 |
| 중요 품질 | 빠른 응답, 큰 글자·명확한 색상, 최소 입력 |
| 주요 불편 | 과도한 경보, 복잡한 용어, 늦은 화면반응 |

### 4.3 권한

- 담당 설비 상태와 경보 조회
- 경보 확인 및 현장상태 입력
- 허용된 1차 조치결과 입력
- 경보 삭제, 임계값 변경, 모델 변경은 불가

## 5. UC-02 정비 담당자

### 5.1 역할과 책임

- 경보와 센서추세를 분석하여 고장가능성을 판단한다.
- 정비 우선순위와 필요한 부품·도구·정비시간을 제안한다.
- 정비작업, 교체부품, 실제 고장원인 및 결과를 기록한다.
- 오경보 또는 미탐 가능성을 데이터 분석가에게 Feedback한다.
- 정비 후 기준값과 설비상태를 확인한다.

### 5.2 사용자 특성

| 항목 | 내용 |
|---|---|
| 기술수준 | 설비와 진단기술 숙련, 데이터 추세 이해 가능 |
| 사용환경 | 정비실, 현장 단말, PC 및 Tablet |
| 필요정보 | 원시·가공 센서추세, 임계값, 이상점수, 정비·고장이력 |
| 중요 품질 | 상세조회, 비교, 필터, Export, 사건 연결 |
| 주요 불편 | 센서와 정비기록 분리, 고장원인 Label 불일치 |

### 5.3 권한

- 담당·관련 설비의 상세 데이터 조회
- 경보 담당자 지정과 정비상태 갱신
- 정비작업·원인·부품·결과 입력
- 임계값·모델 배포·사용자 권한 변경은 불가

## 6. UC-03 생산 관리자

### 6.1 역할과 책임

- 위험설비와 생산영향을 비교하여 정비 우선순위를 결정한다.
- 생산계획과 정비창을 조정한다.
- 반복고장, 가동률, 경보처리시간 및 정비성과를 검토한다.
- 중대한 위험과 장기 미조치 항목을 상위 책임자에게 보고한다.

### 6.2 정보요구

- 공장·라인·설비별 상태요약
- 위험도와 예상 생산영향
- 미확인·미조치 경보와 경과시간
- MTBF, MTTR, 가동률, 정비건수 및 반복고장
- 주·월간 추세와 개선결과

### 6.3 권한

- 담당 조직의 KPI와 상세상태 조회
- 정비 우선순위와 일정 의견 입력
- 주요 경보 Escalation 확인
- 기술설정, 모델, 사용자권한 변경은 불가

## 7. UC-04 시스템 관리자

### 7.1 역할과 책임

- 설비, 센서, Gateway, 사용자와 역할을 등록·변경·비활성화한다.
- 서비스, Database, 저장용량, 통신상태와 로그를 감시한다.
- 백업, 복구, 인증서, 비밀번호 정책 및 접근권한을 관리한다.
- 시스템 변경과 장애조치 내역을 감사 가능하게 기록한다.

### 7.2 권한

- 장치·사용자·역할·정책·연결설정 관리
- 시스템 상태·로그·감사기록 조회
- 백업·복구 및 승인된 업데이트 수행
- 경보의 실제 원인이나 정비결과를 임의 변경할 수 없음

## 8. UC-05 데이터 분석가

### 8.1 역할과 책임

- 데이터 품질을 분석하고 학습대상 데이터셋을 정의한다.
- 특징을 생성하고 AI 모델을 직접 학습·검증·시험한다.
- 모델의 Recall, Precision, F1, ROC-AUC, 오경보율 및 탐지선행시간을 평가한다.
- 기존모델과 신규모델을 비교하고 배포승인을 요청한다.
- Drift, 성능저하, Feedback과 실제 고장결과를 분석한다.

### 8.2 권한

- 승인된 범위의 센서·경보·정비 데이터 조회
- 데이터셋·특징·모델·평가결과 등록
- 모델 배포요청과 Rollback 요청
- 운영모델의 직접 배포 및 사용자정보 조회는 불가

## 9. UC-06 안전·품질 담당자

### 9.1 역할과 책임

- 안전·품질 관련 경보와 조치가 절차에 따라 처리되었는지 확인한다.
- 장기 미조치 경보, 경보억제 및 권한변경을 감사한다.
- 사고·불량과 설비상태·정비이력 간 연관성을 검토한다.
- 개선조치와 재발방지 결과를 확인한다.

### 9.2 권한

- 경보, 정비, 변경, 감사로그 읽기
- 감사의견과 개선요청 등록
- 원시데이터, 경보 및 로그 삭제 불가

## 10. UC-07 경영·공장 책임자

### 10.1 역할과 책임

- 예지보전 도입성과와 주요 공장위험을 확인한다.
- 가동률 개선, 중단시간 감소, 정비비용 및 투자우선순위를 검토한다.
- 조직·라인별 장기추세와 개선활동을 승인한다.

### 10.2 정보요구

- 전체 공장 상태와 Top Risk 설비
- 생산중단시간, 예방정비율, 가동률 및 비용 추세
- 주요 사고·반복고장과 개선조치
- 시스템·AI 모델의 신뢰도와 운영상태 요약

## 11. 권한 매트릭스

| 기능 | 작업자 | 정비 | 생산관리 | 시스템관리 | 분석가 | 안전·품질 | 책임자 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 설비상태 조회 | R | R | R | R | R | R | R |
| 상세 센서추세 | 제한 | R | R | R | R | R | 요약 |
| 경보 확인 | R | R | R | R | R | R | 요약 |
| 정비결과 입력 | 제한 | C/U | 승인정보 | - | Feedback | R | - |
| 장치·사용자 설정 | - | - | - | C/U/D | - | 감사 | - |
| 평가모델 등록 | - | Feedback | 조회 | 운영지원 | C/U | 조회 | 요약 |
| 모델 배포승인 | - | C | C | 실행 | 요청 | C | 정책승인 |
| 감사로그 조회 | 본인 | 담당 | 조직 | 전체 | 본인 | 전체 | 요약 |

> R=Read, C=Create, U=Update, D=Deactivate. 실제 권한은 최소권한 원칙에 따라 세분화한다.

## 12. User Class 기반 설계원칙

- 작업자 화면은 현재상태와 즉시 행동을 우선하고 전문용어를 최소화한다.
- 정비 화면은 원시·가공 데이터, 비교, 이력 및 원인분석 기능을 제공한다.
- 관리자 화면은 위험과 생산영향을 요약하고 상세화면으로 Drill-down할 수 있어야 한다.
- 시스템 관리와 AI 모델 관리는 일반 운영화면과 논리적으로 분리한다.
- 위험작업, 경보억제, 모델배포 및 권한변경은 사유·승인·감사기록을 요구한다.
