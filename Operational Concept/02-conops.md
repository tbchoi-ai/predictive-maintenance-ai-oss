# Smart Factory 예지보전 시스템 운용개념서(CONOPS)

## 1. 문서 개요

| 항목 | 내용 |
|---|---|
| 관련 Issue | #3 CONOPS·User Class·운용 시나리오 |
| 문서 목적 | 시스템의 운용환경, 경계, 운용모드, 사용자 역할과 전체 운용흐름 정의 |
| 주요 독자 | 생산 작업자, 정비 담당자, 관리자, 개발·운영팀, 교수자 |
| 기준 버전 | Version 1.0 - 요구사항 기준선 입력자료 |

## 2. 운용 목적

본 시스템의 운용 목적은 생산설비의 상태를 지속적으로 관찰하고 고장징후를 조기에 식별하여, 생산 작업자와 정비 담당자가 실제 고장이 발생하기 전에 적절한 조치를 수행하도록 지원하는 것이다. 시스템은 의사결정 지원도구이며, 설비 자동정지나 정비승인을 독립적으로 수행하지 않는다.

## 3. 운용환경

| 구분 | 운용환경 |
|---|---|
| 물리환경 | 공장 생산라인, 설비실, 정비실 및 관리사무실 |
| 대상설비 | 모터, 베어링, 펌프, 컨베이어, 압축기 및 회전체 장비 |
| 센서 | 진동, 온도, 전류, 회전속도, 압력 등 상태센서 |
| 현장장치 | PLC, IoT Gateway, Edge Computer, 현장 작업자 단말 |
| 서버환경 | 현장 서버 또는 교육용 Cloud/Server 환경 |
| 네트워크 | 센서망, 현장 LAN, 관리망 및 제한된 외부연계망 |
| 운용시간 | 생산운영 중 연속 감시, 정비시간 중 점검·설정·모델관리 |

| IoT Gateway | 표준화된 센서 메시지, 연결상태 | 프로토콜 변환과 버퍼링 수행 |
| 생산 작업자 | 경보확인, 현장상태, 1차 조치결과 | 실제 설비 운전과 안전조치 책임 |
| 정비 담당자 | 진단결과, 정비권고, 작업결과 | 정비판단과 물리적 정비 수행 |
| 생산 관리자 | 위험설비, 가동률, 정비 우선순위 | 생산계획과 정비일정 승인 |
| MES/CMMS | 설비정보, 작업지시, 정비이력 | 외부 시스템의 정확성과 가용성 책임 |
| 알림 서비스 | Email, SMS 또는 조직 메시지 | 최종 전달성공은 외부서비스 영향 |

## 5. 운용 전·후 비교

| 구분 | 도입 전 | 도입 후 |
|---|---|---|
| 상태확인 | 정기순찰, 장비별 화면, 수기기록 | 통합 Dashboard와 설비별 상태추세 |
| 이상탐지 | 단일 임계값과 작업자 경험 | 규칙 기반 및 AI 기반 다변량 분석 |
| 경보관리 | 경보 발생·해제 중심 | 우선순위, 확인, 담당, 조치, 종료이력 관리 |
| 정비결정 | 고장 후 또는 고정주기 정비 | 위험도, 생산영향, 이력 기반 우선순위 |
| 모델관리 | 적용근거와 버전 확인 어려움 | 데이터·특징·모델·성능·승인이력 관리 |
| 개선활동 | 데이터와 정비결과 분리 | 조치결과를 데이터와 연결하여 재학습에 활용 |

## 6. 상위 운용흐름

1. 센서와 Gateway가 설비 상태 데이터를 생성·전송한다.
2. 시스템이 장치인증, 메시지 형식, 시간, 값의 범위와 누락을 확인한다.
3. 정상 데이터는 시계열 저장소에 기록되고 Dashboard에 반영된다.
4. 규칙 기반 탐지와 AI 모델이 설비상태, 이상점수 및 고장가능성을 계산한다.
5. 위험수준에 따라 정보, 주의, 경고, 위험 경보가 생성된다.
6. 작업자 또는 정비 담당자가 경보를 확인하고 현장상태를 점검한다.
7. 담당자가 조치, 실제 원인, 교체부품 및 결과를 기록한다.
8. 시스템은 경보와 정비결과를 연결하여 보고서와 모델개선 자료를 제공한다.

## 9. 데이터 운용개념

- 모든 데이터에는 설비 ID, 센서 ID, 측정시각, 수집시각, 단위 및 품질상태가 포함된다.
- 원시데이터와 전처리 데이터는 구분하여 저장한다.
- 누락, 지연, 범위초과 및 중복 데이터는 품질상태와 함께 기록한다.
- 모델입력 데이터와 결과에는 데이터셋, 특징, 모델 버전을 연결한다.
- 경보, 사용자 확인, 정비작업 및 실제 고장원인을 동일 사건 ID로 연결한다.
- 보존기간이 지난 데이터는 승인된 정책에 따라 요약 또는 삭제한다.

## 10. AI 운용개념

- 학생이 직접 데이터 전처리, 특징생성, 모델학습 및 성능평가를 수행한다.
- 신규모델은 기존 승인모델과 동일한 Test Set 또는 승인된 평가절차로 비교한다.
- Recall, Precision, F1, ROC-AUC, 오경보율 및 탐지선행시간을 함께 평가한다.
- 목표성능을 만족하지 못하거나 데이터 Drift가 탐지되면 기존모델을 유지한다.
- 모델 결과는 권고정보이며 최종 정비판단은 담당자가 수행한다.
- 사용자 Feedback과 실제 정비결과는 검토 후 학습 Label로 사용할 수 있다.

| Gateway 단절 | 로컬 버퍼링 또는 데이터 누락경보 | 저장순서·중복 검증 후 재전송 |
| 서버장애 | 상태모니터링과 알림, 제한서비스 제공 | 서비스·Database 무결성 확인 |
| 모델서비스 장애 | 규칙 기반 분석으로 저하운영 | 모델서비스 복구와 결과 일관성 점검 |
| 알림서비스 장애 | Dashboard 경보 유지, 전달실패 기록 | 미전달 경보 재전송 또는 대체수단 사용 |
| 데이터베이스 장애 | 쓰기제한 또는 임시버퍼, 관리자 경보 | 복구·백업검증·누락데이터 보정 |

## 12. 운용 정책

- 위험경보는 작업자가 임의 삭제할 수 없으며 확인과 조치상태만 변경한다.
- 정비 중 경보억제는 권한 있는 사용자가 사유와 종료시각을 입력해야 한다.
- AI 모델 배포는 성능평가와 승인기록 없이는 수행하지 않는다.
- 장치·사용자·권한·모델 변경은 감사로그에 기록한다.
- 시스템 권고보다 현장 안전절차와 설비제조사 지침을 우선한다.

## 13. CONOPS 완료기준

- 시스템 목적, 경계, 외부개체 및 운용환경이 정의된다.
- 정상, 경고, 성능저하, 정비, 모델관리 및 시스템관리 모드가 구분된다.
- 데이터 수집에서 정비결과 Feedback까지 전체 흐름이 설명된다.
- AI 결과의 책임한계와 운영승인 절차가 명시된다.
- User Class와 상세 운용 시나리오를 작성할 수 있는 입력정보가 제공된다.
